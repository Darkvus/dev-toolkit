# Frontend Directory Structure

Frontends are organized **by feature**, and features mirror the backend bounded contexts / microservices (see [[backend-microservices-directory-structure]]). A developer looking for "vehicles" finds everything about it in one folder.

## Layout

```
src/
├── app/                         # Application shell: wiring only, no feature logic
│   ├── providers.tsx            # ThemeProvider, QueryClientProvider, Toaster
│   └── router.tsx               # Route table (lazy-loads feature pages)
├── components/
│   ├── ui/                      # shadcn/ui primitives (vendored, see frontend-shadcn-ui)
│   ├── theme-provider.tsx       # Generated by the shadcn Vite template
│   └── <shared-component>.tsx   # App-wide compositions (confirm-dialog, page-header, ...)
├── features/
│   └── <feature>/               # One folder per bounded context / resource
│       ├── api/                 # Query keys, queries and mutations (TanStack Query)
│       ├── components/          # Components used only by this feature
│       ├── pages/               # Route-level components
│       ├── schemas/             # Zod schemas: API contracts, form models, filter types
│       └── hooks/               # Feature-specific hooks (optional)
├── hooks/                       # Shared hooks (alias from components.json)
├── lib/
│   ├── api/                     # HTTP client, ApiError, pagination helpers
│   ├── format.ts                # Unit/locale formatting (see frontend-units-and-formatting)
│   ├── forms.ts                 # Form helpers (applyApiErrors, pickDirty)
│   └── utils.ts                 # cn()
├── test/                        # Test setup, MSW server, render helpers
├── index.css                    # Tailwind + theme tokens
└── main.tsx                     # Entry point: providers + RouterProvider
```

Tests live next to the file they test: `vehicle-form.tsx` → `vehicle-form.test.tsx`.

## Naming

| Item | Convention | Example |
| --- | --- | --- |
| Files and folders | kebab-case | `vehicle-form.tsx`, `features/ride-hailing/` |
| Components | PascalCase, named export | `export function VehicleForm()` |
| Hooks | `use` + camelCase | `useVehicles`, `useUpdateVehicle` |
| Zod schemas | camelCase + `Schema` | `vehicleSchema`, `vehicleFormSchema` |
| Inferred types | PascalCase | `type Vehicle = z.infer<typeof vehicleSchema>` |
| Query key factories | `<resource>Keys` | `vehicleKeys.list(filters)` |
| Pages | `<Resource>Page` | `VehiclesPage`, `VehicleDetailPage` |

Use **named exports** everywhere (no default exports), so renames are caught by the compiler and imports are greppable.

## Import boundaries

1. Always import through the `@/` alias, never with long relative paths (`../../../`).
2. `components/ui` imports nothing from `features/` or `app/`.
3. `lib/` imports nothing from `features/`, `components/` or `app/`: it is framework-light infrastructure.
4. A feature may import from `components/`, `hooks/` and `lib/`. It must **not** import another feature's internals. If two features need the same thing, move it to `components/` or `lib/`, or expose it deliberately from the owning feature's `api/`.
5. `app/` is the only place that knows every feature (routes and providers).
6. No barrel files (`index.ts` re-exporting a folder): they hide dependencies and slow Vite down.

Correct example:

```tsx
// src/features/trips/components/trip-summary.tsx
import { Card, CardContent } from "@/components/ui/card"
import { formatDistance } from "@/lib/format"
import { useVehicle } from "@/features/vehicles/api/vehicles" // public API of another feature
```

Incorrect example:

```tsx
// src/features/trips/components/trip-summary.tsx
import { VehicleForm } from "../../vehicles/components/vehicle-form" // another feature's internals + relative path
import { vehicleSchema } from "@/features/vehicles/schemas/vehicle"  // coupling to another feature's schema
```

## Routing

- Routes are declared in `src/app/router.tsx` with React Router's `createBrowserRouter`.
- Route paths use plural kebab-case resources, matching the API: `/vehicles`, `/vehicles/:vehicleId`.
- Page components are lazy-loaded per feature so each feature is its own chunk:

```tsx
import { createBrowserRouter } from "react-router"

export const router = createBrowserRouter([
  {
    path: "/vehicles",
    lazy: async () => ({ Component: (await import("@/features/vehicles/pages/vehicles-page")).VehiclesPage }),
  },
])
```

- Table filters, sorting and pagination live in the URL search params, not in component state (see [[frontend-data-tables]]).

## Environment variables

- Only `VITE_`-prefixed variables reach the browser, and everything in the bundle is public. Never put secrets in them.
- Declare them in `.env.example` and type them in `src/vite-env.d.ts`:

```ts
interface ImportMetaEnv {
  readonly VITE_API_URL: string
}
```
